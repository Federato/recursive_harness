4. Verifying it — three checks, using the fields above

A correct-looking row 137 can still be wrong if an item's link silently failed to match.

Check 1 — does every linked item's ID resolve to a real building?

Special Class Inputs
B (Item 1)C (Item 2)D (Item 3)E (Item 4)
Row 22 — Linked Building Item ID1 - 1—1 - 11 - 3
Row 23 (new) — Building ID Found? TRUEn/aTRUE
FALSE — no building "1 - 3" exists
 
' 'Special Class Inputs'!B23
=IF(B21<>"Yes", "n/a",
   IF(COUNTIF('Location Inputs'!$B$5:$K$5, B22)>0, "TRUE", "FALSE"))
⚠This is the failure mode that's easy to miss. Item 4 typed 1 - 3 — Location 1 only has two buildings, so this is either a typo for 1 - 2 or a building that hasn't been added yet. Without this check, the item silently contributes nothing to any building's row 137b — SUMIF just never matches — and the workbook doesn't error, it quietly undercounts. A filterable TRUE/FALSE/"n/a" row catches this at the item level.

Check 2 — no duplicate Item IDs on Location Inputs

' one cell, e.g. Location Inputs row 6 in a summary column, or a dedicated dashboard tab
=IF(SUMPRODUCT(1/COUNTIF('Location Inputs'!$B$5:$K$5,'Location Inputs'!$B$5:$K$5))=COUNTA('Location Inputs'!$B$5:$K$5),
   "OK -- all Item IDs unique", "DUPLICATE FOUND -- check Location Inputs")
•Since Location Inputs!B5 is already a formula off Location # and Building # (confirmed in §1), this should never actually fire in practice — it's cheap insurance against a copy-pasted row that duplicated its Location/Building numbers along with everything else.

Check 3 — grand-total reconciliation

' claimed: every item that says it's linked, regardless of whether the link actually resolved
=SUMIF('Special Class Inputs'!$B$21:$K$21, "Yes", 'Special Class Inputs'!$B$16:$K$16)

' landed: sum of every building's own row 137b across all 10 building columns
=SUM(CoreScratchpad!$B$137b:$K$137b)

' the check itself
=IF(Claimed=Landed, "OK -- every linked item accounted for",
   "MISMATCH -- " & (Claimed-Landed) & " unaccounted for -- check Row 23 for FALSE")
•With Item 4's bad link from Check 1, "claimed" would include its 5,000 (it did say "Yes") but "landed" wouldn't, since SUMIF never matched it — reporting a 5,000 mismatch. This is the backstop: even if someone ignores Check 1's row-level flag, this one cell reports the exact dollar amount that fell through. Put it on a summary tab, not buried inside Special Class Inputs.
