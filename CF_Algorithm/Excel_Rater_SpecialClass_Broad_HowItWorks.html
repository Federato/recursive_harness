How Special Class Broad Form Rating Works

Written: 2026-09-15. Source: CommercialPropertySpecialClassRules.Rule.xml and CommercialPropertySpecialClassBroadCoverageRules.Rule.xml, read directly this session, plus a full 47-state sweep of both the rate tables and the state rule files. Companion to Excel_Rater_SpecialClass_HowItWorks.html (Basic Group I) and Excel_Rater_SpecialClass_BGII_HowItWorks.html (Basic Group II) — this page is Special Class's own Broad form, standalone.

Status: traced, not built. Nothing here has been entered into the live workbook. On Special Class Worksheet, Basic Group I is complete through premium and Basic Group II stops at DeductibleFactorBasicGroupII; Broad has no rows at all.

1. What's different about Special Class's Broad, in plain English

This is by far the shortest chain in the whole coverage — five steps against Basic Group II's ten. Broad form for Special Class does almost nothing clever: it takes one flat countrywide rate, multiplies by the loss cost multiplier, applies coinsurance, applies two deductible factors, and stops.

The reason it is so short is that Special Class's Broad rate is construction-blind. Building's Broad form picks a base rate by construction type; Special Class hard-codes the key to "Frame" and reads that single row no matter what the property actually is. There is no territory, no symbol, no protection class, no class description — the base rate is the same 0.015 for every Special Class item countrywide.

The consequence worth understanding: two Special Class items in the same state with wildly different hazard — a concrete bridge and a wood cooling tower — get the identical Broad base rate. Every dimension that separates them in Basic Group I and Basic Group II disappears here. If a Broad-form Special Class premium looks suspiciously flat across a schedule, this is why, and it is correct.

2. The rating chain, step by step

#StepWhat it does
1BroadBaseRate Two conditions, both required: CauseOfLossToUse = "Broad" and PolicyType = "Commercial Property Policy". If either fails, 0.0. When both pass, LookupBroadFormBaseRate keys on State|CW plus the literal constants "Frame" and "Bldg" against BroadFormBaseRate — the construction key is a hard-coded literal, not the item's real construction. CW value 0.015.
2BroadRate BroadBaseRate × LossCostMultiplier, rounded to 3 dp. Two factors — the shortest rate step anywhere in this coverage. No numeric value, no symbol, no exclusion factors.
3AdjustedBroadRate BroadRate × CoinsuranceFactor, 3 dp. Uses the shared CoinsuranceFactor the item's Basic Group I chain already computed — not Basic Group II's flat 1.5 surcharge branch. Broad has no coinsurance rule of its own.
4DeductibleFactorBroad A flat three-way Choose, far simpler than Basic Group II's two-level version: Deductible = "250" → LookupDeductible250Factor("Broad") = 1.05; a real deductible → LookupDeductibleFactor keyed on Deductible, TotAmtInsuranceToUse and "Other Cause Of Loss"; anything else → 0.0. No wind/hail branch at all — Broad never looks at WindstormOrHailDeductible.
5FinalBroadRate AdjustedBroadRate × DeductibleByLocationFactor × DeductibleFactorBroad — and note it reads the shared DeductibleByLocationFactor (Basic Group I's), not a Broad-specific one. There is no BroadDeductibleByLocationFactor datadef.

3. The full formula, end to end

BroadBaseRate =
    LookupBroadFormBaseRate(State|CW, "Frame", "Bldg")      # CW 0.015
        if CauseOfLossToUse = "Broad" and PolicyType = "Commercial Property Policy"
    else 0.0

BroadRate =
    BroadBaseRate × LossCostMultiplier
    (round to 3 dp)

AdjustedBroadRate =
    BroadRate × CoinsuranceFactor      # the shared BGI coinsurance result
    (round to 3 dp)

DeductibleFactorBroad =
    LookupDeductible250Factor("Broad")                      # 1.05    if Deductible = "250"
    elif Deductible is a real value:
        LookupDeductibleFactor(Deductible, TotAmtInsuranceToUse, "Other Cause Of Loss")
    else 0.0

FinalBroadRate =
    AdjustedBroadRate × DeductibleByLocationFactor × DeductibleFactorBroad
    (round to 3 dp)

Premium (scheduled, IncludedInBlkt <> "Yes") =
    round((Limit/100) × FinalBroadRate × PackageModFactor
          × MultiPremiumAndDispersionCreditFactor × IRPMFactor, 0)
      × CyberIncidentExclusionFactorBroad × CyberIncidentExclusionCOLExcptnsFactorBroad

Premium (blanket, IncludedInBlkt = "Yes", zero if BlktTotalFullValueAmount = 0) =
    round((BlktLimit/100) × (FullSpecialClassValue/BlktTotalFullValueAmount) × BlktBroadAvgRate
          × PackageModFactor × MultiPremiumAndDispersionCreditFactor × IRPMFactor, 0)
      × CyberIncidentExclusionFactorBroad × CyberIncidentExclusionCOLExcptnsFactorBroad

Five rating-chain steps, against Basic Group I's eight and Basic Group II's ten.

4. Premium

CommercialPropertySpecialClassBroadCoverageRules.Rule.xml is structurally identical to the Basic Group I and Basic Group II premium files, confirmed by direct read: same two branches (blanket / scheduled), BlktBroadAvgRate and FinalBroadRate substituted for the other forms' datadefs, and the two cyber factors applied outside the rounded product. No Legal Liability branch.

The two cyber factors here are the Broad members of the same policy-level pair documented for Basic Group II — set once per policy in CommercialPropertyRules.Rule.xml, never copied onto the item. CyberIncidentExclusionFactorBroad is 0.995 when CP 10 75 is attached; CyberIncidentExclusionCOLExcptnsFactorBroad runs 1.000 / 1.000 / 0.998 / 0.997 across the Full Limit and Sublimit × aggregate combinations — the same values Basic Group II carries.

Not verified for Broad specifically: New York overrides both cyber rules for Basic Group II (killing the CP 10 75 credit outright and turning CP 10 76 into a 1.005 surcharge). Whether NY does the same to the Broad pair has not been checked — it is likely, given the pattern, but it is an assumption until swept.

5. What's shared with other forms vs. genuinely Broad-specific

PieceStatusNote
BroadFormBaseRateShared table, Special-Class-only keyBuilding and Personal Property read this same table, but pick their real construction type. Special Class always reads the "Frame" row. Same table, fundamentally different use.
CoinsuranceFactorFully sharedThe item's own Basic Group I result, reused as-is. Broad has no coinsurance rule — which means all six state variations documented for Basic Group I (FL's 1.42/1.14, NY's graduated scale, PR's missing sub-80% branch, AL/KS/RI's public-institutional branch) flow straight through to Broad.
DeductibleByLocationFactorFully sharedBasic Group I's, not a Broad-specific field. CW 0.995, no state deviates. Note this is the plain by-location factor, not Basic Group II's — there is no wind/hail indicator gate on this one.
DeductibleFactor, cause-of-loss keyShared with Special, not with the Basic groupsBroad passes "Other Cause Of Loss". Basic Group I passes "Basic Group I", Basic Group II passes "Basic Group II". Same table, three different columns of values — identical only at countrywide; every state that files its own table files genuinely different numbers per column.
Deductible250FactorShared table, own keyBroad passes "Broad" → CW 1.05, same as Basic. (Special and All Other are 1.10.)
Wind/hail anythingAbsentNo exclusion factor, no wind/hail deductible branch, no indicator. Broad carries no windstorm dimension whatsoever.
StdPropPolGroupIFactorAbsent from the chainComputed during shared prep but never multiplied into any Broad step — and moot anyway, since step 1 zeroes the rate on a Standard Property Policy in 45 states.

6. State deviations — swept, not assumed

Both the rate tables and the 47 state rule files were compared against countrywide. Table sweeps alone would have missed all five of the rule overrides below.

State(s)What deviatesEffect
PRBroadFormBaseRate tableFiles its own Frame/Bldg row at 0.011 against CW's 0.015 — roughly a 27% lower base rate. The only state to deviate on this table.
AL, KS, RISetBroadRate ruleAdds a third multiplier: BroadRate = BroadBaseRate × LossCostMultiplier × PublicInstitutionalPlanFactor. The factor is 0.85 in all three states — a 15% credit — applied when PublicInstitutionalPlanApply = "Yes" and coinsurance is 90% or 100% (blanket coinsurance if the item is blanketed). Otherwise 1.0.
KS, NYSetBroadBaseRate ruleDrop the PolicyType = "Commercial Property Policy" half of the gate; the test is just CauseOfLossToUse = "Broad". Consistent with KS and NY not offering Standard Property Policy for Special Class at all — the condition is redundant there rather than a real difference in outcome.
FLSetFinalBroadRate ruleDrops DeductibleByLocationFactor entirely: FinalBroadRate = AdjustedBroadRate × DeductibleFactorBroad. Consistent with Florida also blanking SetDeductibleByLocationFactor to an empty sequence. Florida gets no by-location deductible credit on Broad.
All other 42—Countrywide rules and the CW BroadFormBaseRate row throughout.
The deductible tables are the real state story, as everywhere in this coverage. 46 of 47 states file their own DeductibleFactor table with state-specific limit bands, and the "Other Cause Of Loss" column Broad reads is a genuinely different set of values from the Basic Group columns. The extraction already done for Basic Group II (SpecialClass_BGII_DeductibleFactors.xlsx) does not cover Broad — it was filtered to "Basic Group II". A Broad build needs the same pull re-run on the other column.

7. Why this one should be cheap to build

Five steps, three of which are plain products, and every table it touches is already extracted or already in the workbook:

  • Step 1 is one constant per state — 46 states at 0.015, Puerto Rico at 0.011. A two-column lookup, or arguably a single IF.
  • Step 3 reuses the coinsurance cell already built for Basic Group I. No new work.
  • Step 5 reuses the by-location cell already built for Basic Group I, with a Florida exception.
  • Step 4 is the only genuine lift: a re-pull of the deductible table on the "Other Cause Of Loss" column, all 47 states with their own bands.

Against Basic Group II — which needed a class-description numeric value, a symbol, a territory, an exclusion factor, a policy-type factor, two coinsurance mechanisms and a two-level deductible branch — Broad is a fraction of the work.
