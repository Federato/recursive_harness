STEP 2 / 8

The filed rule, in plain English

Two completely different triggers behind one factor, depending on policy type.

Policy TypeWhat has to be trueThen
Commercial Property Policya Vandalism Exclusion record exists on the Business Income item — cause of loss is never testedlook up the factor
Standard Property PolicyCause of Loss is Fire, Fire and Allied Lines, Fire, Vandalism and Allied Lines or Fire, Sprinkler Leakage and Allied Lines — the endorsement is never testedlook up the factor
either, gate fails—1.0
either, gate passes but ClassCode is blank—0.0 — zero rate, silently
⚠"Fire, Vandalism and Allied Lines" is in the qualifying list. A cause of loss that explicitly includes vandalism still earns the vandalism-exclusion credit on a Standard Property Policy. That reads wrong on its face; it is what is filed, and no rule elsewhere reverses it. Reproduced here rather than corrected.

Three states override the rule: VT, KS and NY drop the outer gate entirely — no policy-type test, no cause-of-loss list. In those three the endorsement is required regardless of policy type, which is handled in step 3.

C249fx=OR(AND('Policy Inputs'!$C$3="Commercial Property Policy",'Special Class Inputs'!C$26="Yes"),AND('Policy Inputs'!$C$3="Standard Property Policy",ISNA(MATCH(C$2,{"VT","KS","NY"},0)),ISNUMBER(MATCH('Special Class Inputs'!C$12,{"Fire","Fire and Allied Lines","Fire, Vandalism and Allied Lines","Fire, Sprinkler Leakage and Allied Lines"},0))))
BC
249SC BI — Vandalism Excl Gate?TRUE

ISNA(MATCH(C$2,{"VT","KS","NY"},0)) is what removes the Standard-Property-Policy arm in those three states — it reads “state is not one of these three.” On a Commercial Property Policy the first arm carries regardless of state, so no exclusion list is needed there.

Use MATCH, not COUNTIF, for both list tests. COUNTIF’s first argument must be a real cell range — hand it an array constant like {"VT","KS","NY"} and Excel rejects the formula outright. MATCH takes array constants happily, so ISNA(MATCH(…)) and ISNUMBER(MATCH(…)) are the working equivalents of “not in the list” and “in the list.”

If you would rather avoid array constants altogether, expand both tests to explicit comparisons — C$2<>"VT",C$2<>"KS",C$2<>"NY" and OR(…="Fire",…="Fire and Allied Lines",…). Same result, longer formula, no array syntax to get wrong.

On IFERROR → 0 rather than 1: that is what the filed rule does. A gate that passes with an unmatched or blank class code falls through to 0.0, not to a neutral 1. Leaving it at 0 keeps the workbook honest; add a check cell if you would rather see it than have it quietly zero a premium.
