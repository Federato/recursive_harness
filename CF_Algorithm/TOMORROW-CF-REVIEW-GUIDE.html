02

The method — already proven, don't reinvent it

AGENTS.md Part 2 documents the exact briefing pattern that produced all five of today's fully-documented coverages. Use it again, verbatim.

1

Read the template first — the Building doc for structure and depth; for anything structurally close to an already-documented family, also read that sibling doc. An Earthquake pass should start with Business Income's own EQ section, since that's the one place in this project an EQ chain has already been traced.

2

Enumerate before assuming — grep the real Rules directory for actual file names before tracing anything. This project's own rule #1, and the reason the original 97-family count turned out to be less than half the real 243.

3

Cite everything — file name + line number for every rule reference; table name + confirmed file path + row count, not just existence, for every data claim.

4

Never guess — anything genuinely unresolvable from the ERC files alone goes into the report as an open question. See SpecificGroupIRate in Excel_Rater_BasicGroupI.md §9 for a recent example done correctly: no rule was found for it anywhere, and that absence was reported as-is.

5

Report back structurally — files written, the biggest structural differences versus the closest documented sibling, and a bullet list of open questions. Every time.

!

Two standing corrections, learned the hard way twice already. "Table exists" and "table has a usable data row" are different claims — verify both, every time. And when a search returns zero results for something you'd expect to exist, that's a prompt to widen the search, not a reportable absence — the original 97-family undercount happened because one filename pattern was trusted without checking whether ISO used a second one, which is exactly where Earthquake and Flood turned out to be hiding.
