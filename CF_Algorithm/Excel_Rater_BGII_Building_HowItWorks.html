How Basic Group II Building Rating Works

Written: 2026-09-14. Source: Excel_Rater_BasicGroupII.md §4, §7, §8 (traced 2026-09-08) and CauseOfLoss_Building_RatingAlgorithms.md.

Status: documented, marked ✅ built in Excel_Rater_CoreCoverages_RatingGrid.html. Basic Group II has no Specific/Tentative rating path — confirmed structurally absent, same standing as Broad and Special.

1. What Basic Group II is, in plain English

Basic Group II covers windstorm or hail, riot or civil commotion, vandalism, sprinkler leakage, and sinkhole collapse. It's rated by resolving a construction symbol — a single letter or letter-pair code — from the building's construction type and number of stories, then pricing off that symbol crossed with a Basic-Group-II- specific rating territory. Class code and construction code, the two values that drive most of this workbook's other rating chains, only enter this one indirectly, through a handful of named-class overrides.

2. The rating chain, step by step

#StepWhat it does
−1ConstructionSymbol LookupBasicGroupIIConstructionSymbol(State|CW, ConstructionType, NumStories), then replaced in order by whichever override matches first: a roof-construction override for certain additional classes, a named-class override (0580/0585 and related codes), or an oil-distributing-stations override. Unchanged if none match. This has to resolve before anything else in the chain can run.
1BaseRate LookupBasicGroupIIRate(State|CW, BasicGroupIIRatingTerr, ConstructionSymbol, "Bldg"), requiring both ConstructionSymbol and territory non-blank, else 0.0. Territory is baked directly into this lookup key — there's no separate multiplicative territory factor anywhere downstream.
2LowestBaseRate LookupLowestBasicGroupIIRate(State|CW, ConstructionSymbol, "Bldg") — same table family as step 1 but keyed on symbol alone, no territory. Only consumed later, in the wind/hail-excluded branch of COLAdj.
3NumericValue A 4-way branch: 1.0 if windstorm/hail is excluded on this building; a class-code-specific lookup for four named classes (0580, 0585, 1150, 1300, 1650); an open-sides lookup if OpenSides = Y and ConstructionCode ≠ 0; otherwise 1.0.
4Rate BaseRate × LCM × NumericValue × RoofSurfacingACVFactor × RoofSurfacingCosmeticExclFactor × BCEGFactor — round to 3dp. A pure product, no addends of any kind.
5COLAdj Zero if the selected cause of loss is one of four fire-only combinations. Otherwise, if wind/hail isn't excluded: Rate × StdPropPolGroupIIFactor. If wind/hail is excluded: a full rebuild — LowestBaseRate × LCM × RoofSurfacingACVFactor × RoofSurfacingCosmeticExclFactor × WindstormOrHailExclFactor × StdPropPolGroupIIFactor.
—Wind/hail-exclusion eligibility Unresolvable in 8 states — AR, DC, FL, KS, NY, PR, RI, TX file zero rows for both LowestBasicGroupIIRate and WindstormOrHailExclFactor, together. Inferred (not confirmed against the manual) to mean these states may not permit excluding wind/hail from a CPP at all — plausible given several are coastal/wind-pool states, but flagged as inference. Full mechanism and worked examples in Excel_Rater_BGII_WindHailExclusionEligibility_Walkthrough.html.
6CoinsuranceFactor Flat lookup (State|CW, "Y") when Coinsurance is 50%/60%/70%/None; otherwise this building's own Basic Group I CoinsuranceFactor is copied in directly rather than recomputed.
7LOIFactor Four-way: a blanket copy when Bldg_IncludedInBlkt = "Yes"; a Builders-Risk-specific lookup (0.0 if the Builders Risk limit is absent); a general lookup for other covered coverage types (0.0 if absent); flat 1.0 for Leasehold Interest, Legal Liability, or No Coverage.
8AdjustedRateCOLAdj × CoinsuranceFactor × LOIFactor.
9BGIIDeductibleByLocationFactor Its own field, separate from the plain DeductibleByLocationFactor used elsewhere. Only computed (via a lookup, else 1.0) when WindstormHailIndicator = 0 and a real by-location wind/hail-deductible record exists.
10DeductibleFactor Outer test: if Bldg_WindstormOrHailDeductible is blank, "Not Applicable", or equal to Deductible, fall through to a Choose on Deductible keyed to the "Basic Group II"-specific slice of the shared DeductibleFactor table. Otherwise branch on Bldg_WindstormOrHailDeductible instead — dollar amounts read the same table; percentage amounts (1%/2%/5%) read an entirely separate WindstormOrHailDeductibleFactor table, gated on WindstormHailIndicator = 1.
11FinalRate AdjustedRate × BGIIDeductibleByLocationFactor × DeductibleFactor × MultiResidentialPropSpecialCreditFactor.
An orphaned factor found while tracing this form: OperationalUnitWindstormOrHailExclusionFactor is computed (gated on BldgIncludedInOperationalUnit = "Yes" and an ancestor-level count of exclusion forms in the same Operational Unit) but a full trace of every reference to it in CommercialPropertyStructureRules.Rule.xml found it's never multiplied into Rate, NumericValue, or FinalRate anywhere. Unconfirmed whether some premium/summary rule outside this file consumes it, or whether it's genuinely unused. Not built into this workbook pending that answer.

4. The full formula, end to end

ConstructionSymbol =
    LookupBasicGroupIIConstructionSymbol(State|CW, ConstructionType, NumStories)
    <then, in order, replaced by whichever override matches first:>
        LookupBGIISymbolAdditionalClassesRoofConstruction(...)
        LookupBasicGroupIISymbolAdditionalClasses(...)              # class codes 0580/0585 and related
        LookupBasicGroupIISymbolOilDistributingStations(...)
    <else unchanged>

BaseRate =
    LookupBasicGroupIIRate(State|CW, BasicGroupIIRatingTerr, ConstructionSymbol, "Bldg")
        if ConstructionSymbol and BasicGroupIIRatingTerr are both non-blank
    else 0.0

LowestBaseRate =
    LookupLowestBasicGroupIIRate(State|CW, ConstructionSymbol, "Bldg")
        if ConstructionSymbol is non-blank
    else 0.0

NumericValue =
    1.0                                                              if WindstormOrHailExclusion = Y
    elif ClassCode in (0580,0585,1150,1300,1650):
        LookupGroupIINumericValue(State|CW, ClassCode, ConstructionCode)
    elif OpenSides = Y and ConstructionCode ≠ 0:
        LookupGroupIIOpenSidesNumericValue(State|CW, ConstructionCode)
    else:
        1.0

Rate =
    BaseRate × LCM × NumericValue × RoofSurfacingACVFactor × RoofSurfacingCosmeticExclFactor × BCEGFactor
    (round to 3 dp)

COLAdj =
    0.0    if CauseOfLoss in ("Fire","Fire and Vandalism","Fire and Sprinkler Leakage",
                               "Fire, Vandalism and Sprinkler Leakage")
    elif WindstormOrHailExclusion ≠ Y:
        Rate × StdPropPolGroupIIFactor
    else:
        LowestBaseRate × LCM × RoofSurfacingACVFactor × RoofSurfacingCosmeticExclFactor
          × WindstormOrHailExclFactor × StdPropPolGroupIIFactor

CoinsuranceFactor =
    LookupBasicGroupIIFlatCoinsuranceFactor(State|CW, "Y")   if Coinsurance in ("50%","60%","70%","None")
    else CoinsuranceFactor   # this building's own Basic Group I result, copied in

LOIFactor =
    <blanket copy>                                            if Bldg_IncludedInBlkt = "Yes"
    elif Bldg_CovType = "Builders Risk":
        LookupBasicGroupIILOIFactorWithArgs(...) or 0.0 if the Builders Risk limit is absent
    elif Bldg_CovType not in ("Leasehold Interest","Legal Liability","No Coverage"):
        LookupBasicGroupIILOIFactorBldg(...) or 0.0 if absent
    else:
        1.0

AdjustedRate = COLAdj × CoinsuranceFactor × LOIFactor

BGIIDeductibleByLocationFactor =
    LookupDeductibleByLocationFactor(...)
        if WindstormHailIndicator = 0
           and a wind/hail-by-location record exists with a non-blank value
    else 1.0

DeductibleFactor =
    <Deductible-keyed Choose, reading the "Basic Group II"-keyed slice of DeductibleFactor>
        if Bldg_WindstormOrHailDeductible is blank, "Not Applicable", or = Deductible
    else <branch on Bldg_WindstormOrHailDeductible instead — dollar amounts use the same table;
          percentage amounts (1%/2%/5%) use a separate WindstormOrHailDeductibleFactor table entirely>

FinalRate = AdjustedRate × BGIIDeductibleByLocationFactor × DeductibleFactor × MultiResidentialPropSpecialCreditFactor

Bldg_Premium =
    if Bldg_CovType in ("Building","Builders Risk","Improvements and Betterments","Condominium Association")
       and Bldg_IncludedInBlkt = "No":
        round(IRPMFactor × MultiPremiumAndDispersionCreditFactor × PackageModFactor × FinalRate × (Bldg_Limit/100), 0)
          × CyberIncidentExclusionFactorBGII × CyberIncidentExclusionCOLExcptnsFactorBGII
    elif Bldg_CovType = "Legal Liability":
        [not built this pass]
    elif Bldg_IncludedInBlkt = "Yes":
        [blanket branch — truncates the limit ratio, not built this pass]
    else:
        0.0
One validation worth building alongside the formula, per the source doc's own flag: if a percentage wind/hail deductible (1%/2%/5%) is ever selected while WindstormHailIndicator ≠ 1, the dollar-only branch's Or list won't match any of the eight dollar constants and falls to its Otherwise → 0.0 — silently zeroing the entire FinalRate. Rater-side input validation should prevent percentage options from ever being paired with WindstormHailIndicator ≠ 1.
