1. What Special Class is, in plain English

Special Class covers named, scheduled classes of property that don't fit generic Building or Personal Property rating — commodities, agricultural products, signs, antennas, and similar items that ISO gives their own filed rate rather than pricing off construction type. Where Building is rated by what the structure is made of, Special Class is rated by what the scheduled item is — a free-text/named ClassDescription (e.g. "Aircraft Stored in the Open") converted through a 71-option lookup table into the actual rate-table key.

Four cause-of-loss chains exist, same four forms as Building — Basic Group I, Basic Group II, Broad, Special — plus a fifth, Earthquake, that's native to this same rule file rather than an outside endorsement. This page covers Basic Group I only, the shortest and simplest of the four; the others are summarized at the end for context.

2. The open question, resolved: there is no Specific/Tentative path for Special Class

Confirmed, not just presumed by analogy. Earlier analysis of this project flagged Special Class's Specific/Tentative status as "presumed absent, unverified" — a guess based on Building's pattern, not a checked fact. Now checked: a full-text search of CauseOfLoss_SpecialClass_RatingAlgorithms.md for RatingType, Specific, and Tentative returns zero matches, anywhere in the document — not in Basic Group I, not in any of the other three forms. Special Class has exactly one rating path per cause-of-loss form: the scheduled rate built below. There's nothing to neutralize a factor list against, because there's no second path to compare it to.

This means a "Special Class Specific/Tentative" build-process doc, structured the way the Building/Contents/ Business Income ones are, isn't just unbuilt — like Basic Group II, Broad, and Special before it, there's nothing there to build. The rest of this page instead does what is useful at this stage: trace how Special Class's one path actually works, and hold it up against Building's Basic Group I chain to show exactly where the two diverge.

Open question carried over from the source doc: ProtectionClassFactor may be orphaned. The rule file computes a standalone ProtectionClassFactor (line 5724, run last, after all five cause-of-loss chains) — but a full-text search for anywhere it's read turns up only its own two null-guard checks. It's never multiplied into Basic Group I, Basic Group II, Broad, Special, or Earthquake's rate chains. Protection class instead enters Basic Group I's rate through the base-rate lookup key (ProtectionClassToUse), as row 2 above describes. Whether the standalone factor feeds some stat/reporting rule not traced here, or is genuinely vestigial, is unresolved — flagged in the source doc as an open question, not answered here either.

4. The full formula, end to end

ConvertedOption = LookupSpecialClassDescriptionConvertedOption(State|CW, ClassDescription)

BaseRate = LookupBasicGroupIRateSpecialClass(State|CW, ConvertedOption, ProtectionClassToUse)
           if ConvertedOption and ProtectionClassToUse both non-blank
           else 0.0

Rate = BaseRate × LossCostMultiplier    (3dp, only when currently null)

COLAdj = Rate × VandalismExclFactor × StdPropPolGroupIFactor    (3dp, unconditional)

AdjustedRate = COLAdj × CoinsuranceFactor    [no LOI factor]

FinalRate = AdjustedRate × DeductibleByLocationFactor × DeductibleFactorBasicGroupI

Premium (scheduled, IncludedInBlkt <> "Yes") =
    round((Limit/100) × FinalRate × PackageModFactor × MultiPremiumAndDispersionCreditFactor × IRPMFactor, 0)
      × CyberIncidentExclusionFactorBGI × CyberIncidentExclusionCOLExcptnsFactorBGI

Premium (blanket, IncludedInBlkt = "Yes", zero if BlktTotalFullValueAmount = 0) =
    round((BlktLimit/100) × (FullSpecialClassValue/BlktTotalFullValueAmount) × BlktBasicGroupIAvgRate
          × PackageModFactor × MultiPremiumAndDispersionCreditFactor × IRPMFactor, 0)
      × CyberIncidentExclusionFactorBGI × CyberIncidentExclusionCOLExcptnsFactorBGI

Seven rating-chain steps total — one shorter than Building's own Basic Group I (8 steps), because Special Class has no LOI-factor step at all.

What you don't need to ask for. Because of the absences confirmed in §3, none of the following Building-specific inputs feed Special Class at all: ConstructionCode/ConstructionType, roof-surfacing condition, sprinkler-system status (for this cause-of-loss adjustment specifically), substandard-condition and vacant-building flags, or a multi-residential indicator. If a Special Class item entry screen ends up collecting any of these, that's scope creep from Building's form, not something this rating chain actually reads.
