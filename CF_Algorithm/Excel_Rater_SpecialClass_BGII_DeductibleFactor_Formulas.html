STEP 4 / 9

Model the WindstormHailIndicator gate

The percentage path is only allowed to fire when the percentage deductible is actually doing meaningful work — that is what the indicator decides. Put the new block on CoreScratchpad from row 225; the sheet is populated through 223, so nothing is displaced.

225SC BGII — W/H Ded is Percentage?FALSE
226SC BGII — Indicator Threshold0
227SC BGII — WindstormHailIndicator0

The thresholds, in plain English. A 1% deductible counts as meaningful at 100,000 of insured value or more; 2% at 50,000; 5% at 20,000. Florida sets the bar at roughly half — 50,001 / 25,001 / 10,001 — so Florida risks trip the indicator sooner.

Note the odd Florida numbers. ISO filed 50,001, not 50,000, which makes Florida’s test strictly “more than” where countrywide is “at or above”. The >= in C227 combined with the 50,001 threshold reproduces that exactly — do not round it to 50,000.

This same indicator already governs step 8 of the chain. BGIIDeductibleByLocationFactor (worksheet row 35) is forced to 1.0 whenever the indicator is 1. The two credits are mutually exclusive by design: you get the large percentage credit or the small by-location credit, never both. Once C227 exists, row 35 should point at it rather than assuming 0.

⚠Do not copy the band operators between steps 5 and 6. The dollar table uses Limit_Over < limit <= Limit_UpTo; the percentage table uses Limit_From <= limit < Limit_LessThan. Both sets of boundaries are round numbers — 100,000, 250,000, 1,000,000 — exactly where real limits cluster.

Why the leading exclusions. This row must return 0 whenever the wind/hail deductible is a percentage, is absent, or simply matches the policy deductible — in all three cases the filed rule sends the item down the main-deductible path instead (step 8). Getting this wrong would double-count the credit.

The 250 branch reads 'Special Class'!$BI$2 rather than a hard-coded 1.05, so if that block is ever state-expanded the formula follows it.

Reads exactly as the rule does: if the indicator tripped, take the percentage factor; else if the wind/hail deductible differs from the policy deductible, take the dollar factor; otherwise zero — which step 8 then reads as “no separate wind/hail deductible applies.”

The case worth understanding: a percentage deductible selected but below its threshold lands here at 0, and step 8 turns that into a zero factor and a zero premium. That is not a bug in these formulas — it is what ISO filed. The check row in step 8 surfaces it.

The 250 and “Not Applicable” branches are not optional. A 250 deductible has no row in the dollar table — ISO prices it through the separate surcharge table. Without that branch a 250 deductible returns 0 and zeroes the premium.

On leaving a miss at 0 rather than defaulting to 1: that is what the rule does — it falls through to 0.0. Row 233 makes it visible instead of silent. If you would rather fail safe, wrap C36 as =IF(CoreScratchpad!C232=0,1,CoreScratchpad!C232) — but that prices a broken lookup as though no deductible credit applied, which is a real quote going out wrong. The check row is the better trade.

While you are in there: worksheet row 35 (BGIIDeductibleByLocationFactor) should now read =IF(CoreScratchpad!C227=1,1,0.995) rather than assuming the indicator is always 0. The two credits are mutually exclusive, and until now the workbook had no indicator to test.
