STEP 4 / 7

Dollar factor

Banded SUMPRODUCT. Operators are exclusive-from, inclusive-to — Limit_Over < limit <= Limit_UpTo.

CFRater1.01.xlsb — CoreScratchpad
New rows
C236fx=IF(C$235=0,0,SUMPRODUCT(('Special Class'!$CA$2:$CA$6744=C$2)*('Special Class'!$CB$2:$CB$6744=C$235)*('Special Class'!$CC$2:$CC$6744<C$217)*('Special Class'!$CD$2:$CD$6744>=C$217)*'Special Class'!$CE$2:$CE$6744))
BC
236SC Broad — Dollar Factor0.91

Why SUMPRODUCT rather than a row-offset lookup: 45 of the 46 states file their own version of this table with their own limit bands — Ohio's second band ends at 175,000 where countrywide's ends at 100,000 — so there is no shared offset arithmetic to reuse. A banded SUMPRODUCT does not care how each state cuts its bands.

One fix in the rows above this

Not part of the deductible factor, but it multiplies into the same rate.

⚠Row 54, DeductibleByLocationFactor, shows 0.995 for Florida — it should be 1. Florida overrides SetDeductibleByLocationFactor to an empty sequence and separately overrides SetFinalBroadRate to drop the term from the product entirely. As currently built, Florida's Broad rate is 0.5% light.
CFRater1.01.xlsb — CoreScratchpad
Suggested
row 54 srcfx=IF(AND('Special Class Inputs'!C$23="Yes",'Special Class Inputs'!C$22<>"",'Special Class Inputs'!C$22<>"Not Applicable",C$2<>"FL"),0.995,1)

Returning 1 in Florida gives the same number as Florida’s rule dropping the term. It is not structurally identical to what ISO filed — ISO removes the factor rather than neutralising it — but for a plain multiplier the result is the same.
