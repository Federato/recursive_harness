◆

What's constant, what actually diverges

✓Factor is one shared value, not four. Confirmed by call order: SetFactor runs after both SetBGIRatesAndFactors and SetBGIIRatesAndFactors have already finished. It can never differ between BGI and BGII for the same building — and it never exists at all for Broad or Special.
✓BuildersRiskFactor is also one shared value. Computed once during shared prep (SetBuildersRiskFactor, before any per-form chain runs), read by BGI's and BGII's COLAdj — same gate (ClassCodeToUse="1150", CovType≠"Extra Expense Only"), confirmed CW-only 2.0 constant, zero state overrides across all 47 states.
⚠BGII's wind/hail-exclusion branch is confirmed missing from the live workbook, both Building and Contents. The floor-rate lookup (LowestBaseRate) is correctly wired; the WindstormOrHailExclFactor table is never looked up anywhere in CoreScratchpad, and CAUSE OF LOSS ADJUSTMENT is an unconditional RATE × StdPropPolGroupIIFactor with no branch at all. Business Income hasn't been built yet, so this is a design note for that build, not a live gap in this coverage specifically.
✓Broad and Special are structural twins of each other, not of BGI/BGII. Same premium-file shape (exact CauseOfLossToUse equality gate, not a hardcoded 1), same "no Factor, straight Copy to FinalRate" pattern. Broad has no COLAdj at all; Special's COLAdj is the simplest of any form that has one (a single unconditional product, no branching).
⚠BGII is the most Building-copy-heavy form in the coverage. Four of the five inputs feeding Rate are literal Building copies (BasicGroupIISymbolToUse, BasicGroupIIRatingTerr, BasicGroupIINumericValue, BCEGFactor) — only BGIIBaseRateAdjustmentFactor is genuinely independent math at that stage. BaseRate itself is technically its own lookup, but keyed entirely on Building's own field, so it lands on the same number either way.
