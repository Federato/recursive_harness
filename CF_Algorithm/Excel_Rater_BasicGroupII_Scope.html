Not a renamed version of the same chain — a structurally different rate key, plus two mechanics BGI never needed.

Building — the full 13-value chain

Calc_Building_BGII, one row per building. Same if/then formula shape as the flow diagrams in Excel_Rater_Wireframes.html.

ConstructionSymbol = Lookup(BasicGroupIIConstructionSymbol: ConstructionType, NumStories)
    then replaced, in order, by whichever override matches:
    Lookup(...RoofConstruction) → Lookup(...AdditionalClasses, e.g. 0580/0585) → Lookup(...OilDistributingStations)

Terr = Locations_Buildings.BasicGroupIIRatingTerr   (copied down — no local territory-factor rule, unlike Basic Group I)

BaseRate = Lookup(BasicGroupIIRate: Terr, Symbol, "Bldg")   if both non-blank else 0.0
LowestBaseRate = Lookup(LowestBasicGroupIIRate: Symbol, "Bldg")   (no territory key)

NumericValue =
    1.0                                                    if WindstormOrHailExclusion = Y
    elif ClassCode in (0580,0585,1150,1300,1650): Lookup(GroupIINumericValue: ClassCode, ConstructionCode)
    elif OpenSides = Y and ConstructionCode <> 0:  Lookup(GroupIIOpenSidesNumericValue: ConstructionCode)
    else: 1.0

Rate = BaseRate × LCM × NumericValue × RoofSurfacingACVFactor × RoofSurfacingCosmeticExclFactor × BCEGFactor   (round 3dp)

COLAdj =
    0.0   if CauseOfLoss in ("Fire","Fire and Vandalism","Fire and Sprinkler Leakage","Fire, Vandalism and Sprinkler Leakage")
    elif WindstormOrHailExclusion <> Y:
        Rate × StdPropPolGroupIIFactor
    else:
        LowestBaseRate × LCM × RoofSurfacingACVFactor × RoofSurfacingCosmeticExclFactor × WindstormOrHailExclFactor × StdPropPolGroupIIFactor

CoinsuranceFactor = Lookup(flat, "Y") if Coinsurance in ("50%","60%","70%","None") else <shared Basic Group I value>

LOIFactor =
    <blanket copy>                       if Bldg_IncludedInBlkt = "Yes"
    elif Bldg_CovType = "Builders Risk":  LookupWithArgs(...) or 0.0 if limit absent
    elif Bldg_CovType not in ("Leasehold Interest","Legal Liability","No Coverage"): Lookup(BasicGroupIILOIFactorBldg)
    else: 1.0

AdjustedRate = COLAdj × CoinsuranceFactor × LOIFactor

BGIIDeductibleByLocationFactor = Lookup(...)  if WindstormHailIndicator = 0 and a wind/hail-by-location record exists  else 1.0

DeductibleFactor =
    <same-shape Choose, but reads DeductibleFactor's "Basic Group II"-keyed slice, NOT BGI's own
     "Other Cause Of Loss" slice — corrected 2026-09-08, see the callout below>
        if Bldg_WindstormOrHailDeductible blank/N-A/= Deductible
    else <branch on Bldg_WindstormOrHailDeductible — dollar amounts use the same
     "Basic Group II" table; percentage amounts (1%/2%/5%) use a separate WindstormOrHailDeductibleFactor
     table entirely, gated on WindstormHailIndicator=1>

FinalRate = AdjustedRate × BGIIDeductibleByLocationFactor × DeductibleFactor × MultiResidentialPropSpecialCreditFactor

Bldg_Premium =
    if Bldg_CovType in ("Building","Builders Risk","Improvements and Betterments","Condominium Association") and Bldg_IncludedInBlkt = "No":
        round(IRPMFactor × MultiPremiumAndDispersionCreditFactor × PackageModFactor × FinalRate × (Bldg_Limit/100), 0)
          × CyberIncidentExclusionFactorBGII × CyberIncidentExclusionCOLExcptnsFactorBGII
    elif Bldg_CovType = "Legal Liability": [not built this pass]
    elif Bldg_IncludedInBlkt = "Yes": [blanket branch, Truncate(BlktLimit/100) — not built this pass]
    else: 0.0
⚠Corrected 2026-09-08: DeductibleFactor is NOT the same table Basic Group I reads. The table has a 4th key column, CauseOfLossDeductible, filed with three distinct values (Basic Group I / Basic Group II / Other Cause Of Loss). BGI keys on "Other Cause Of Loss"; BGII keys on "Basic Group II". Identical at CW (0 diffs, 80 rows) — genuinely different in every state that files its own table (130+ differing rows/state). Do not reuse BldgBGIRating's existing deductible table for this step. Corrected pull, all 46 non-PR states: BGII_DeductibleFactor.xlsx. One exception: the flat Deductible="250" branch genuinely is shared (keyed on group name "Basic", not form-specific).
⚠Percentage wind/hail deductibles (1%/2%/5%) use a third, separate table — WindstormOrHailDeductibleFactor, reached via a different rule gated on WindstormHailIndicator=1, checked before the dollar-amount branch. If a percentage value is selected while that indicator isn't 1, the dollar-only branch's 8-way Or won't match and falls to 0.0 — silently zeroing the entire FinalRate. Validate this pairing on the input side.
✓The BGIIDeductibleByLocationFactor/DeductibleFactor and MultiResidentialPropSpecialCreditFactor lines already have dedicated, worked-example walkthroughs: Excel_Rater_BGII_DeductibleFactor_Walkthrough.html and Excel_Rater_MultiResCredit_Walkthrough.html + BGI_MultiResidentialPropSpecialCredit.xlsx (shared mechanism with BGI, nothing new to build).
⚠"WindstormOrHailExclusion = Y" above is shorthand. Corrected 2026-09-08: it's not a stored boolean — the rule tests whether a scheduled exclusion record exists for this building (NotExist AtInputDataDef="CommercialPropertyWindstormOrHailExclusionTable/..."), nested inside the Building's own datadef with Premises/Building Number fields — confirmed building-level, not policy-level. Manual citation: ISO Rule 74.A.2.a, Building. A plain Yes/No column on Locations_Buildings is still the right shape to build; it just resolves to "does a record exist," not a literal flag read. OpenSides, by contrast, genuinely is a plain stored Yes/No field — no schedule, no derivation.
⚠Separate, unresolved finding: OperationalUnitWindstormOrHailExclusionFactor — a different mechanism from the per-building exclusion above. Fires only when a building is flagged part of an "Operational Unit" (a schedule of grouped buildings, same concept used in blanket rating/flood/business income elsewhere) and an ancestor-level count shows any building in that unit has an exclusion form scheduled — not just this one. Traced every reference to it in CommercialPropertyStructureRules.Rule.xml: it's set but never multiplied into Rate, NumericValue, or FinalRate anywhere in that file. Unconfirmed whether it's consumed in a premium/summary file not yet checked, or genuinely unused — not built pending that answer.

Contents — the full 12-value chain

Calc_Contents_BGII, one row per building — same symbol/territory shape as Building, no roof factors anywhere, one fewer LOI branch.

Symbol, Terr = Locations_Buildings.ConstructionSymbol / BasicGroupIIRatingTerr   (same pulled-not-computed columns Building reads)

BaseRate = Lookup(BasicGroupIIRate: Terr, Symbol, "PersProp")   (same table Building reads, different covType)
LowestBaseRate = Lookup(LowestBasicGroupIIRate: Symbol, "PersProp")

NumericValue = (same three-way logic as Building, keyed on BldgClassCode)

Rate = BaseRate × LCM × NumericValue × BCEGFactor   (no roof factor at any branch)

COLAdj =
    0.0   if fire-only cause of loss or PP_ValuablePapers = "Y"
    elif WindstormOrHailExclusion <> Y:
        Rate × StdPropPolGroupIIFactor
    else:
        LowestBaseRate × LCM × WindstormOrHailExclFactor × StdPropPolGroupIIFactor   (still no roof factors)

CoinsuranceFactor = <same flat/shared logic as Building>

LOIFactor =
    <blanket copy>   if PP_IncludedInBlkt = "Yes"
    elif PP_CovForm not in ("Legal Liability Coverage Form","Tobacco Sales Warehouse Coverage Form") and OccupTotalLOIToUse > 0:
        Lookup(BasicGroupIILOIFactorPersProp: OccupTotalLOIToUse)
    else: 1.0                                       (no separate Builders Risk branch, unlike Building)

AdjustedRate = LOIFactor × COLAdj × CoinsuranceFactor

BGIIDeductibleByLocationFactor = Lookup(...)  if PP_WindstormHailIndicator = 0 and a record exists  else 1.0

DeductibleFactor = <same local Choose used on the Building tab, "Basic Group II"-keyed slice>   (★ documented deviation, same as Basic Group I)

FinalRate = AdjustedRate × BGIIDeductibleByLocationFactor × DeductibleFactor   (no multi-res multiplier, any branch)

PP_Premium =
    round(IRPMFactor × MultiPremiumAndDispersionCreditFactor × PackageModFactor × FinalRate × (PP_Limit/100), 0)
      × CyberIncidentExclusionFactorBGII × CyberIncidentExclusionCOLExcptnsFactorBGII
!One rounding divergence to remember when the blanket branch gets built: Basic Group I's blanket premium divides the limit ratio plainly (BlktLimit / 100); Basic Group II's truncates it first (Truncate(BlktLimit / 100)) — a naive copy-and-rename from Basic Group I would get this wrong, for both Building and Contents.
