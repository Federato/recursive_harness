How Special Class Basic Group II Rating Works

Written: 2026-09-14. 1. What's different about Special Class's Basic Group II, in plain English

Same perils as Building's Basic Group II — windstorm/hail, riot/civil commotion, vandalism, sprinkler leakage, sinkhole. The rate build-up is 10 steps, one shorter than Building's 11, because Special Class never derives its own construction symbol the way Building does — there's no SetBasicGroupIISymbol rule anywhere in CommercialPropertySpecialClassRules.Rule.xml at all.

Open question, confirmed by grep, not resolved: BasicGroupIISymbol is read directly wherever this chain needs it, but nothing in this ruleset ever assigns it. It's either a raw data-entry field on the Special Class item, or copied down from somewhere outside this ruleset — unresolved from the rule file alone.

2. The rating chain, step by step

#StepWhat it does
1BasicGroupIINumericValue If no CommercialPropertyWindstormOrHailExclusionSpecialClass record exists: = BasicGroupIISymbolNum. Otherwise 1.0. BasicGroupIISymbolNum is set during shared prep via LookupSpecialClassBasicGroupIINumber, keyed on State|CW + the raw ClassDescription (not the converted option) against matrix SpecialClassBasicGroupIINumber — a named-class lookup, not Building's ClassCode/ ConstructionCode/OpenSides logic.
2BaseRate Requires BasicGroupIIRatingTerr and BasicGroupIISymbol both non-blank, else 0.0. LookupBasicGroupIIRate keys on State|CW/Territory/Symbol/"Bldg" — the exact same BasicGroupIIRate table Building's own chain reads, confirmed by matching MatrixFromConstant name. Everything already built in BGII_BaseRate_Building.xlsx/_FL.xlsx (per-state correct-edition resolution, the FL zero-rows finding, Montana's BaseRate data) applies here directly, no separate pull needed.
3LowestBaseRate Same shape as Building — shared LowestBasicGroupIIRate matrix, keyed on State|CW/Symbol/ "Bldg" (no territory). Only consumed by the wind/hail-excluded branch of COLAdj, step 5 below.
4Rate BasicGroupIIBaseRate × LossCostMultiplier × BasicGroupIINumericValue — three factors, not Building's six. No roof-surfacing ACV factor, no roof-surfacing cosmetic-exclusion factor, no BCEG factor — confirmed absent, Special Class carries no roof-condition or building-code-effectiveness dimension anywhere in this datadef group.
5COLAdj Gate is narrower than Building's — checks only "Fire" and "Fire and Vandalism" (no "...and Sprinkler Leakage" variants, consistent with Special Class's Basic Group I having no sprinkler-leakage dimension either). If matched: 0.0. Else if no wind/hail exclusion: BasicGroupIIRate × StdPropPolGroupIIFactor. Else (wind/hail excluded): a rebuild — LowestBasicGroupIIBaseRate × LossCostMultiplier × WindstormOrHailExclFactor × StdPropPolGroupIIFactor — same two-path shape as Building, but without the roof-surfacing/cosmetic factors Building applies in that branch, since Special Class never introduced them upstream.
6CoinsuranceFactor Same shape as Building: flat lookup (LookupBasicGroupIIFlatCoinsuranceFactor, State|CW + "Y") when Coinsurance is 50%/60%/70%/None; else copies the shared CoinsuranceFactor this item's own Basic Group I chain already computed. CW flat value 1.5 — a surcharge, not a credit. Already captured in SpecialClass_CoinsuranceFactor_Tables.xlsx, BGIIFlatCoinsuranceFactor sheet.
7AdjustedRate COLAdj × CoinsuranceFactor — two factors, same shape as Basic Group I (no LOI factor, consistent chain-wide across this whole coverage).
8BGIIDeductibleByLocationFactor Same conditions as Building (WindstormHailIndicator = 0 and a by-location record with a real WindstormOrHailDeductible), but reads CommercialPropertyDeductiblesByLocationSpecialClassTable — Special Class's own by-location deductible datadef, not Building's.
9DeductibleFactorBasicGroupII Same two-level structure as Building — outer test on whether a distinct wind/hail deductible applies, inner Choose on Deductible/WindstormOrHailDeductible.
10FinalRate AdjustedBasicGroupIIRate × BGIIDeductibleByLocationFactor × DeductibleFactorBasicGroupII — three factors, no MultiResidentialPropSpecialCreditFactor, consistent with the whole Special Class datadef group.

3. The full formula, end to end

BasicGroupIINumericValue =
    BasicGroupIISymbolNum      if no CommercialPropertyWindstormOrHailExclusionSpecialClass record exists
    else 1.0

BasicGroupIISymbolNum =
    LookupSpecialClassBasicGroupIINumber(State|CW, ClassDescription)
    <computed once, during shared prep>

BaseRate =
    LookupBasicGroupIIRate(State|CW, BasicGroupIIRatingTerr, BasicGroupIISymbol, "Bldg")
        if BasicGroupIIRatingTerr and BasicGroupIISymbol are both non-blank
    else 0.0

LowestBaseRate =
    LookupLowestBasicGroupIIRate(State|CW, BasicGroupIISymbol, "Bldg")

Rate =
    BasicGroupIIBaseRate × LossCostMultiplier × BasicGroupIINumericValue
    (round to 3 dp)

COLAdj =
    0.0    if CauseOfLossToUse in ("Fire", "Fire and Vandalism")
    elif no windstorm/hail exclusion:
        BasicGroupIIRate × StdPropPolGroupIIFactor
    else:
        LowestBasicGroupIIBaseRate × LossCostMultiplier × WindstormOrHailExclFactor × StdPropPolGroupIIFactor

CoinsuranceFactor =
    LookupBasicGroupIIFlatCoinsuranceFactor(State|CW, "Y")   if Coinsurance in ("50%","60%","70%","None")
    else CoinsuranceFactor   # this item's own Basic Group I result, copied in

AdjustedRate = COLAdj × CoinsuranceFactor

BGIIDeductibleByLocationFactor =
    LookupDeductibleByLocationFactor(...)
        if WindstormHailIndicator = 0
           and a CommercialPropertyDeductiblesByLocationSpecialClassTable record exists with a non-blank
           WindstormOrHailDeductible value
    else 1.0

DeductibleFactorBasicGroupII =
    <Deductible-keyed Choose, same two-level structure as Building>
        if WindstormOrHailDeductible is blank, "Not Applicable", or = Deductible
    else <branch on WindstormOrHailDeductible instead>

FinalBasicGroupIIRate = AdjustedRate × BGIIDeductibleByLocationFactor × DeductibleFactorBasicGroupII

Premium (scheduled, IncludedInBlkt <> "Yes") =
    round((Limit/100) × FinalBasicGroupIIRate × PackageModFactor
          × MultiPremiumAndDispersionCreditFactor × IRPMFactor, 0)
      × CyberIncidentExclusionFactorBGII × CyberIncidentExclusionCOLExcptnsFactorBGII

Premium (blanket, IncludedInBlkt = "Yes", zero if BlktTotalFullValueAmount = 0) =
    round((BlktLimit/100) × (FullSpecialClassValue/BlktTotalFullValueAmount) × BlktBasicGroupIIAvgRate
          × PackageModFactor × MultiPremiumAndDispersionCreditFactor × IRPMFactor, 0)
      × CyberIncidentExclusionFactorBGII × CyberIncidentExclusionCOLExcptnsFactorBGII

Ten rating-chain steps total, one shorter than Building's own Basic Group II (11 steps) — Special Class never derives its own construction symbol, per the open question in §1.

4. Premium

CommercialPropertySpecialClassBasicGroupIICoverageRules.Rule.xml — structurally identical to Special Class's own Basic Group I premium file, confirmed by direct read: SetCoverageOnPolicyIndicator is hard-coded to 1, SetPremium has the same two branches (blanket / scheduled) with BlktBasicGroupIIAvgRate and FinalBasicGroupIIRate substituted for the Group I datadefs, and the CyberIncidentExclusionFactorBGII/CyberIncidentExclusionCOLExcptnsFactorBGII pair applied outside the rounded product, exactly as shown at the bottom of §3's formula block. No Legal Liability branch here either.

5. What's shared with Building vs. genuinely Special-Class-specific

PieceStatusNote
BaseRateFully sharedSame BasicGroupIIRate table, every state finding (FL's Residential/Non-Residential mechanism, Montana's values, the 47-state resolvability sweep) applies directly.
LowestBaseRateFully sharedSame LowestBasicGroupIIRate table.
NumericValueNot sharedBuilding keys on ClassCode/ConstructionCode/OpenSides (GroupIINumericValue, GroupIIOpenSidesNumericValue — including the confirmed Montana deviation on those two tables).
