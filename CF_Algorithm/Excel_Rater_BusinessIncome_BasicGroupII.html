1. The headline finding — most of this chain can be a straight copy of Building's own columns

Basic Group I borrows exactly one value from Building (BaseRate). Basic Group II looks like it does more independent work — five steps instead of three — but tracing every field in the rule XML (not just the ones the source doc's prose called out) shows four of the inputs feeding Rate are literal Copy rules from Building, not independent computation at all. Three different relationships show up across the whole chain, and they should be built three different ways.

Business Income never computes this; it only ever reads it via ../../. A plain cell reference to Calc_Building_BGII's own resolved symbol column. No formula, no lookup.

Same table, same key, same territory → mathematically guaranteed to land on the same number Building's own tab already has. Could be built as a copy of Calc_Building_BGII.BaseRate instead of a second lookup — same result, one less formula to maintain. BuildersRiskFactor Genuinely Business-Income-only — confirmed CW-only constant (2.0), no state ever overrides it, no Building equivalent. Its own lookup/constant — see §4 step 5.
Factor the whole shared step Genuinely Business-Income-only — replaces Building's three separate coinsurance/LOI/deductible steps entirely. No Building equivalent of any kind. The six-branch decision tree — see Excel_Rater_BusinessIncome_FactorDecisionTree.html, identical mechanism for Basic Group I and II.
Practical takeaway: four of the columns feeding Rate (BasicGroupIISymbolToUse, BasicGroupIIRatingTerr, BasicGroupIINumericValue, BCEGFactor) are literal Copy rules from Building — confirmed in the rule XML, not inferred from field-name similarity. Two more (BaseRate, LowestBaseRate) can safely be built as copies even though the rule technically re-derives them — same table, same Building-owned key, guaranteed identical result. That leaves only three genuinely independent pieces of math in this whole form: BGIIBaseRateAdjustmentFactor, BuildersRiskFactor, and the shared Factor step. Of the seven inputs Rate and COLAdj touch, six are either literally Building's cell or might as well be — only BGIIBaseRateAdjustmentFactor and BuildersRiskFactor are Business-Income-only math before you even get to Factor.

4. The algorithm

1Four Building copies, confirmed in the rule XML copy

BasicGroupIISymbolToUse = Calc_Building_BGII.BasicGroupIISymbolToUse -- SetBasicGroupIISymbolToUse, Structure rules only BasicGroupIIRatingTerr = Calc_Building_BGII.BasicGroupIIRatingTerr -- SetBasicGroupIIRatingTerr, line 2767: Copy, one line BasicGroupIINumericValue= Calc_Building_BGII.BasicGroupIINumericValue -- read via ../../, never recomputed BCEGFactor = Calc_Building_BGII.BCEGFactor -- SetBCEGFactor, line 2772: Copy, IsNull-guarded

All four are plain cell references in the workbook — no formula, no lookup. Confirmed by reading each Set* rule directly rather than trusting the field name alone (same discipline that caught the earlier SprinklerLeakageExclNonSprinkleredRate naming trap).

2BaseRate same value as Building's, either copy it or re-derive it

if (BI_MaxPeriod = "Y" or BI_MonthlyLimitOfIndemnity <> "Not Applicable" or BI_CovType = "Extra Expense Only") and BI_BldgIncludedInOperationalUnit = "Y": HighestBusnIncomeBasicGroupIIBaseRate -- blanket/multi-unit, out of scope elif BasicGroupIIRatingTerr <> "" and BasicGroupIISymbolToUse <> "": Lookup(BasicGroupIIRate: State, BasicGroupIIRatingTerr, BasicGroupIISymbolToUse, "Bldg") → falls back to (CW, ...) if the state has no row -- equivalently: Copy(Calc_Building_BGII.BaseRate) -- same table, same key, -- guaranteed same answer, one less formula else: 0.0

2.5LowestBaseRate same relationship

Lookup(LowestBasicGroupIIRate: State, BasicGroupIISymbolToUse, "Bldg") → falls back to (CW, ...) if the state has no row -- equivalently: Copy(Calc_Building_BGII.LowestBaseRate)

3BGIIBaseRateAdjustmentFactor own lookup

Lookup(BaseRateAdjustmentFactor: State, "Basic Group II") → falls back to (CW, "Basic Group II") if the state has no row

4Rate

BaseRate × LCM × BasicGroupIINumericValue × BCEGFactor × BGIIBaseRateAdjustmentFactor -- round to 3dp -- of these five multiplicands, only BaseRate (step 2, same value as -- Building's) and BGIIBaseRateAdjustmentFactor (step 3, genuinely own) aren't a plain -- Building copy -- BasicGroupIINumericValue and BCEGFactor are copies from step 1

5COLAdj own gate, own factor

if no wind/hail-exclusion-for-Business-Income record exists: Rate × BuildersRiskFactor else: LowestBaseRate × LCM × WindstormOrHailExclFactor × BuildersRiskFactor

The gate itself is genuinely different from Basic Group I's (sprinkler-related test) — this is a record-existence check, not a field comparison. BuildersRiskFactor is the same confirmed-CW-only 2.0-constant walked through separately — no per-state variation found anywhere.
