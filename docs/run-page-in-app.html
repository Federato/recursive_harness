A run just finished — what does the app show?

The run file is now a full interactive page: verdict, change block, lead visual, matrix, table. The question is how much of that the /tests page repeats when the run ends, given the file is one click away.

Mockup. Invented numbers. Each panel is the /tests page immediately after the L3 run completes.
1 · The headline and the change block, then send you to the file The app answers “how did it go” without scrolling — counts, and what changed since last time. Anything you have to explore — the matrix, the curve, the per-state detail — lives in the file, which is one click away and is the thing you would send anyway.
Two places, and the boundary has to be obvious. In exchange the app stays a launcher and the file stays the artefact, and neither grows into the other.

2 · Render the whole run page inside the app Everything the file holds, shown in place — you never leave the page you started the run from, and the file is still written for keeping and sending.
One page to build, rendered twice — and that is the risk: two renderers of the same run will drift, and the day they disagree you will not know which one is right. Building it once and embedding it is possible, and is more work than it sounds.
