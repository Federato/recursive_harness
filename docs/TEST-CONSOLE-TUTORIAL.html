What the console is for

The Recursive Harness rates General Liability (GL) and Commercial Property (CP) from ISO's own ERC content. The test console answers one question: where does our rating agree with ISO's, and where haven't we checked yet? ISO's answers come from its Rating-as-a-Service (RaaS). Each request to it is one call, and calls are budgeted.

The console stores every ISO answer. It re-rates each stored request on today's engine and compares the two. The comparison runs across states, coverages and the individual rating paths: the different routes a premium can take, such as "Prem/Ops · units" or "Causes of loss · Special".

Opening it

  • Windows: unzip the package and double-click RecursiveHarness.exe. From the source folder, run start.bat.
  • Mac: unzip the package and double-click start.command. It needs Python 3.9 or newer.

A browser opens at http://127.0.0.1:8765/console. The app's original rating page, "Rate a submission", is still at /. There's a link to it in the console's header.

Only one app at a time. If an older copy is still running, it keeps the port, and the browser shows the old pages. Close every app window (Ctrl-C, or close the console window), then start it once.
Sending to ISO needs credentials. Everything marked free works without them. To send calls, the app needs a raas.env file next to it. Ask Dan; it's never shipped in the package.

The seven screens sit across the top: Coverage Board, Readiness Matrix, Test Plan Builder, Trace Diff, Scenario Workbench, Regression Library and Queue & Run Log. A strip under them shows today's call budget.

Reading the cells

The Board and the Matrix use the same six cell states:

StateMeaningWhat it needs
✓RaaS-verified / PassedEvery in-scope path agrees with ISO within tolerance; no open mismatch; nothing stale.Nothing.
○Internal onlyOur engine has walked it, but at least one path has no ISO answer to compare with.Send scenarios to ISO.
×MismatchAt least one open difference from ISO outside tolerance.Triage in Trace Diff, then re-verify.
↻StaleWe have an answer, but ISO's content in force has changed since.Refresh the stale answers.
–UntestedNo scenario has walked any path here.Find or plan scenarios.
·n/aThe state doesn't file this path. It's never a gap.Nothing.

On the Coverage Board, a number in a cell is how many scenarios walked that path. For a mismatch or a stale cell it reads affected/total.

Free vs. calls to ISO

Every button says what it costs. Free work (rating on our engine, Tier 0 checks, re-running the library) costs nothing. Anything that sends to ISO says call and asks before it sends.

LanePer dayUsed by
Active plans150Plans you commit (quick smoke, board cells, the Plan Builder)
Change & stale refresh50Re-asking ISO where its content changed
Ad hoc & triage50Single sends from the Workbench

That's 250 calls a day in all, and the lanes reset at midnight Eastern. Before any call, the console checks whether ISO has already answered that exact request. A fresh stored answer is reused, not paid for twice. When a lane is full, sending more needs an override with a written reason (Queue & Run Log → Set override).

Walkthrough 1 · Run a quick smoke

A quick smoke rates one retail risk per state at industry-standard selections. It's the fastest way to see that a state rates end to end.

GL retailClass 11127 (clothing stores), $1,000,000 gross sales, premises/operations and products/completed operations together, $1M occurrence / $2M aggregates, occurrence form, no deductibles.
Property retailClass 0567 (Mercantile NOC), Special causes of loss (rates Basic Group I, Basic Group II and Special), joisted masonry, $1M building, $250K contents, 80% coinsurance, replacement cost, $1,000 deductible.

One state

  1. Open Coverage Board and choose General Liability or Commercial Property at the top right.
  2. Click a state's name in the left column. Its panel opens on the right.
  3. Click Run quick smoke for OH…. The console counts the calls: one, or none if ISO already answered.
  4. Click Send now. The console opens Queue & Run Log on the new plan, and the result appears there when ISO answers.

Every state

  1. Open Test Plan Builder. Under Start from, pick Quick smoke · GL retail (one per state) or Quick smoke · Property retail (one per state).
  2. The right-hand panel counts the plan: 51 GL or 46 Property scenarios, less any already answered, against what's left in the active lane today.
  3. Click Commit plan…, give it a name, tick start and click Commit.

Walkthrough 2 · Test one cell from the board

Each Coverage Board cell is one rating path in one state. You can test any cell directly.

  1. On Coverage Board, click a cell, for example OH × Prem/Ops · units.
  2. The panel lists the scenarios already behind the cell. Click a linked one to open it in Trace Diff.
  3. Under Run tests for this cell, click Find scenarios (free). The console rates candidate risks on our engine and keeps only those whose trace actually walks this path. It tries the state's base risk, the smoke risk, then one setting changed at a time, best match first. This takes up to 30 seconds.
  4. Each find shows our premium and whether ISO has answered it. Risks with no fresh answer are ticked.
  5. Click Send ticked to ISO…, check the call count, then click Send now.
"None found" is an honest answer. Some paths aren't reachable by changing one setting: company ELP, specific Property rates, stop-gap ILF, and the per-claim deductibles ISO files at zero. For those, build the request by hand in the Scenario Workbench.

Walkthrough 3 · Close a state's gaps

  1. Open Readiness Matrix. Rows are states; columns are coverages for GL and CP. Each row ends with a readiness figure.
  2. The side panel, Still to test, lists the gaps, most urgent first. Click a gap, or any cell that isn't ✓, to see what's missing and why.
  3. Click Build a test plan from these gaps. The Plan Builder opens with those states and coverages already chosen.
  4. Check the count and click Commit plan… (see walkthrough 6).

The chart under the matrix, Agreement with ISO over time, shows whether agreement is rising as plans finish.

Walkthrough 4 · Investigate a mismatch

  1. Find a × cell on the Board or the Matrix and click a scenario in its panel. It opens in Trace Diff.
  2. Trace Diff lines our worksheet up with ISO's, step by step. It shows the first divergence, what flows from it, and whether this difference has been seen before elsewhere.
  3. Decide the cause and pick a category under Classify this scenario (see the categories), then click Save classification. Only a true engine defect is ours to fix; the others explain the gap.
  4. Copy brief copies a plain-text summary for a ticket or a message.
  5. Once it's fixed or explained, click Promote to Regression Library so every future engine change is checked against it.

Walkthrough 5 · Try a what-if risk

  1. Open Scenario Workbench. Choose the line and state.
  2. For GL, set the controls: class code, exposure, limits, deductibles and so on. The class shows its premium basis, such as "per unit, 50 units" for apartments. For CP, edit the request itself.
  3. Click Rate internally · free. You get our premium, the packages used, and the paths the risk walked.
  4. Check where it applies · free and Run in every state… rate the same settings in every state where they're legal, and count what sending would cost.
  5. Send to RaaS · 1 call… asks ISO from the ad hoc lane. If ISO has already answered this exact request, you can Use the stored answer · free or Spend a call anyway.
  6. Build a plan from this… turns the risk into a plan across states.

Walkthrough 6 · Build a bigger plan

  1. Open Test Plan Builder. Pick the line and the states.
  2. Optionally start from a preset: quick smoke, a QA tier or a layer.
  3. Tick the dimensions to vary and pick their values. For GL class codes, the builder suggests a mix of ten (manufacturing, apartments, lessor's risk, retail, construction), each labelled with its premium basis. Type any other code in the box to add it.
  4. The console combines values pairwise, so every pair of values meets at least once without trying every combination, and adds edge cases. The panel shows the counts: scenarios, already answered (reused), calls, and the active lane left.
  5. Run Tier 0 now · free runs quick sanity checks on our own engine first, such as no zeroed premiums.
  6. Click Commit plan…, name it, choose whether to start now, and click Commit. Each scenario is rated on our engine at commit time; the calls go out from the queue.

Walkthrough 7 · Check nothing broke

The Regression Library holds every scenario ISO has answered that we keep as a check. It's around 400 entries today.

  1. After any engine or content change, open it and click Re-run now · free. Every entry is re-rated on today's engine and compared with ISO's stored answer.
  2. Since the previous run lists what changed: newly agreeing, newly disagreeing, or moved.
  3. Stale answers lists entries where ISO's content has changed since it answered. Each one shows a remedy: re-send to ISO, or refresh our corpus when ISO has a version we don't.
  4. Optionally, Sign off a run to record that someone reviewed it.

Walkthrough 8 · Watch the queue and budget

  1. Open Queue & Run Log. The top shows Today · resets 00:00 ET with each lane's used and left counts.
  2. Plans lists every committed plan with its progress. Pause, resume or Withdraw one there.
  3. Dispatch queue · next up shows the scenarios about to be sent. They go in order of what they'd teach us: a path not yet verified in its state first, then changed content, then edge cases, then the rest. Before each call the console checks again whether ISO has already answered.
  4. The Run log records each call: sent, reused, refused, or capped.
  5. Refused payloads lists requests ISO rejected, with its message, so you can tell a bad input from an engine problem.
Plans send only while the app is open. If you close it, the plan picks up where it left off next time.

Questions

A screen shows "Built in TC-…" or old pages

An older copy of the app is still running. Close all app windows and start it once.

Why is a Property cell "n/a"?

The state doesn't file that path. It's never counted as a gap.

Can I break anything?

Free actions change nothing at ISO. Sends always show the call count and wait for Send now. Stored answers are never deleted; evidence is only added to.

Where's the read-only version?

The Test Console page on Ideation is a snapshot of the matrix, board, library, queue and some Trace Diffs. Nothing there sends or changes anything.
