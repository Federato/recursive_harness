The configuration × jurisdiction matrix — three ways a cell can answer you

Agreed so far: verdict, then a lead visual chosen by layer, then this matrix, then the state table. The open question is what a cell does when you point at it — and it matters because a run file has to open from disk with no server behind it.

Mockup. Invented numbers. The matrix is trimmed to 4 configurations × 20 states so it fits; a real L3 run is 4 × 51.
These are live — try them. Hover the cells. Click the red ones. Each tab behaves the way that option really would.
1 · Every cell is a plain link, with a browser tooltip Hover and the browser shows its own tooltip after a moment. Click and you jump to that state's row in the table below, which highlights. Pure HTML — no <script> anywhere in the file.
The file stays provably inert: nothing in it can execute. The tooltip is the browser's, so it looks plain and takes about a second to appear — you cannot style it or make it instant.

2 · Inline JavaScript Hover shows a styled panel immediately. Click a cell and the table below filters to that configuration. The matrix can also re-sort states by problem count, which pulls the trouble to one side.
A run file would contain executable code. The check that currently asserts run files carry no <script> would have to be split into two — one for "loads nothing from the network", one for "carries no script" — and only the first would still hold.
