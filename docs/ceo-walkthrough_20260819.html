0:00–1:00

What this is, in one breath

No screen yet — say this before you open anything.

  • ISO publishes the General Liability rating rules every carrier in the country has to follow. This engine reads ISO's own filed content and executes it — it doesn't re-implement the rules in our own code.
  • We rate a submission and get a premium the same way ISO's own rating service would, and then we check our answer against ISO's live service, jurisdiction by jurisdiction.
  • What you'll see today: the engine rating something real, the harness that keeps proving it's right, and where that harness now helps find and explain problems, not just count them.
1:00–4:00

The bet: an interpreter, not a rulebook we wrote

ShowFile explorer — ISO_ERC_Files\General_Liability, one folder per state.
  • ISO doesn't publish a document. It publishes a program — over 20,000 rule files across 567 packages, CSV tables and instruction files, one folder per state and edition.
  • The obvious move is to read ISO's rules once and hand-code the logic. The problem: every time ISO refiles — and they refile constantly — that hand-coded logic goes stale, silently, until someone notices a wrong premium.
  • We built the other thing: an interpreter for ISO's own instruction set — 54 instructions, fully specified, executed directly against ISO's files. An ISO update is a file drop, not a code change.
  • The tradeoff, said plainly: every one of those 54 instructions had to be nailed down before anything could run at all. That's why this took real time up front.
4:00–8:00

Rate a real submission, live

Show app.py at / — rate the sample submission.
  • One submission in, one premium out — with every factor that applied, in the order it applied, each one traced back to the exact ISO file it came from. Nothing is a black box here on purpose.
  • Rate the same submission in a second state. Same engine, zero state-specific code — that's the interpreter bet paying off.
  • Now the proof: 51 jurisdictions rate. 50 of those are on our ISO subscription and get checked live against ISO's own rating service — 50 of 50 agree, on the premium and on every field ISO publishes back, not just the number.
  • The two exceptions, said out loud rather than glossed over: Hawaii isn't in our ISO delivery at all, and Puerto Rico rates but isn't on our subscription, so there's nothing to check it against.
8:00–13:00

The QA harness — layers, aggregate, verdict

Show /tests — pick L3 · Limits, then scroll to Aggregate.
  • 50 agreements on one submission is a start, not proof. So there's a second thing running underneath: a harness that varies the submission on purpose and checks every result.
  • Four layers, each changing exactly one thing — the class of business, the limits, the deductibles — so when something disagrees, we know which variable caused it, not just that something's wrong somewhere.
  • Point at the Aggregate table: every scenario ever run, summed per layer, with a colored dot reading the worst outcome at a glance — blue agrees, red needs a look.
  • Point at the verdict cards: one percentage per layer, not one blended number — so a problem in one layer can't hide behind three clean ones.
  • This is the part that scales. Today it's this one product line; the same harness is how we prove out every additional line and every carrier's own rates later.
13:00–16:00

Reviewing a failure, with no API key

ShowAny run file → Review this run →, built yesterday.
  • When a scenario disagrees, someone has to work out why. That used to mean opening the run file and reading data by hand.
  • Now the harness takes a first pass automatically, for free, with no AI call involved — it sorts a refusal into "that's a question for ISO" versus "that's on us," and it checks whether the exact same problem was already explained in a different run.
  • What it can't explain, it turns into a short brief — the evidence, formatted to paste into a conversation like this one — and whatever comes back gets pasted in and kept with the run, clearly marked as a person's answer, not a verified fact.
  • Built and shipped in one day, planned with a written risk list before a line of code — that pace is representative of how this whole project has gone.
16:00–19:00

The honest state — proven, not proven, and why

No new screen — stay on /tests, talk over it.

  • Proven: the engine, one product line, live-checked in 50 states, with a harness that catches its own mistakes before we do.
  • Not yet proven: other lines of business, and — the big one — our own rates rather than ISO's filed ones. The moment we layer in carrier deviations, this same independent check stops being independent, which is exactly why it's sequenced last.
Said plainlyThis is a real internal tool being used daily. It is not yet a product an underwriter opens every morning — no accounts, no concurrency, no saved-quote workflow. That gap is known and sized, not discovered today.
