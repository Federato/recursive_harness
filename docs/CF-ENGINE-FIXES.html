Engine fixes you have authorized

As of 2026-09-24. Every change made to the rating engine’s interpreter during the Property build, each one found by running a case, measured against ISO, and made only on your go. Sources: OPEN-ITEMS.md, CF-ENGINE-FIX-BANDED-LOOKUP.md, CF-ENGINE-FIX-DATE-COMPARE.md, CF-CHUNK9-GOLDEN-CASE.md §8, CF-CHUNK10-GATE.md, CF-CHUNK13-TASKS.md.

In plain English. The engine reads ISO’s rule files and does what they say. Ten times, ISO’s own service did something slightly different from what our engine did with the same rule, and every time ISO’s answer was the one to match. None of these were guesses: each was found by a real case disagreeing with ISO (or failing outright), confirmed with ISO where a live answer was possible, and followed by the full regression. All ten are in the interpreter that General Liability shares (two sit behind Property-only switches), so every one was also checked against all 16 GL test suites.

Each fix in detail

1 A reading loop that also moved where results were written 2026-09-21 ISO-confirmed $255 / $510

In plain English. Blanket rating averages a rate across several buildings. To do that, ISO’s rule loops over a list of detail records reading from each, but it means to keep its running totals on the building. Our engine moved both reading and writing into each detail record, so the totals landed in the wrong place and both buildings priced at $0.

Technical
  • ForEach @AtInputDataDef rebound writes exactly like ForEach @AtDataDef. Frame gained a write_root; an AtInputDataDef loop calls fr.at(item, keep_write_root=True): reads resolve against the item, a bare ToDataDef still writes to the frame that was active before the loop.
  • write_root propagates through with_params and in_rule, so it survives WithArgs, cross-file RunRule and nested loops (the rule has two).
  • Deliberately unchanged: ForEach AtDataDef (chunk 4’s repeating groups need the full rebind) and Locate (its job is to move the write target).
Evidence
  • Golden case: average rate 0.236 → 0.255, premiums $0 → $255 / $510, then matched ISO live to the dollar (C9-13).
  • All chunk 1–8 scripts and all 16 GL suites re-run green. The first engine change since chunk 0.

2 Rate tables that pick a row by two brackets at once 2026-09-22 Hand-derived match

In plain English. Some tables choose a row two ways at once: one number is blended smoothly between rows (e.g. the percent of the building sub-limited), and a second only has to fall in a bracket (e.g. total property value). Our table code only knew one “blend” number per table and refused the rest, so Earthquake sub-limit coverage with a flat-dollar deductible could not be rated at all.

Technical
  • _lookup_banded refused any table whose key_ranges length was not 1. Now every range key is a containment filter in ISO’s filed order, and the one to interpolate is chosen by name from the value range’s RangeKeyCol, never by position.
  • Population: exactly 28 CF tables have two ranges (13 EQ sub-limit flat-deductible, 7 Flood rate-modification, 1 Massachusetts heating-oil table, 7 dead). None have three.
  • Still refuses rather than guess: two interpolated ranges, or a RangeKeyCol that isn’t one of the table’s own ranges. gl_engine/erc/tables.py untouched.
Evidence
  • CP 10 29 case now runs: EQDeductibleFactor 1.376, premium $6, hand-derived from the filed CSV.
  • 16/16 GL suites; chunk 1–9 regression clean (C10-21). Not yet exercised: CP 10 45 (percentage sub-limit, a different 6-table family).

3 Comparing two dates 2026-09-22 ISO-confirmed $272 / $31

In plain English. Leasehold Interest asks “does the lease end after the policy starts?” Our engine could compare numbers but not dates, so it stopped with an error. It now compares dates as dates.

Technical
  • _cmp (behind GreaterThan, LessThan, and the two “or equal” forms) pushed both operands through ip.num, so a date raised. Now: if both operands are dates, compare as dates. Number vs number unchanged; date vs number still refused.
  • 28 ordered date comparisons corpus-wide; 2 premium-bearing (Leasehold SetNumberOfMonths, Builders Risk SetProRate). None were reachable before, because no earlier case supplied the dates.
  • Process lesson: the chunk 11 census checked element names, not operand types. Every census since checks types.
Evidence
  • Chunk 11 golden case: 20 of 20 hand-derived values, $268 + $30; later matched ISO live. Regression clean.

4 A blank date is the earliest date, not “no date” (OI-102) 2026-09-22 ISO-confirmed $272 / $31

In plain English. When a date is left blank, ISO’s rules fill in 1 January year 1. ISO treats that as a real, very early date. We treated it as missing, so any “is X before Y?” test came out no. A Leasehold Interest with no lease start date priced at $0 here and $272 at ISO.

Technical
  • In _cmp only, an operand recognised by _is_date_zero (a dateTime FirstValue falling back to 01/01/0001, or that Constant) orders as date.min. That covers 56 of the 60 such operands.
  • Deliberately unchanged: coerce still reads the sentinel as null, so IsNull, IsNotNull and equality behave as before; the 4 bare Value operands (ISO’s ordering of those is unmeasured); all non-date comparisons.
Evidence
  • Live ISO: missing lease date moved $0 → $272 / $31, = ISO. Regression clean, 51 of 51.

5 0 to the power 0 is 1 (OI-104) 2026-09-22 ISO-confirmed $0

In plain English. Leasehold Interest discounts a lease with a power calculation. With no interest rate and no months left it asks for 00. Python refuses; ISO’s .NET says 1. So does any Leasehold building sent without its lease details, because ISO’s rules create an empty lease record for it. We crashed; ISO prices $0. Now we say 1 and price $0.

Technical
  • _power: base == 0 and exp == 0 returns 1 (rounded as the element asks), traced power-zero-zero. The refusal for a non-positive base with a fractional exponent stays.
  • One regression expectation moved, correctly: chunk 8’s zero case 3 had pinned the old crash; it now rates $0, as chunk 8’s own map predicted.
Evidence
  • Live ISO case Z13: $0 both sides. Regression clean for chunks 0–11 after the one expectation update.

6 “Days from A to B” had the wrong sign (OI-107) 2026-09-22 ISO-confirmed 257 days GL ERP untested

In plain English. We computed “days from B to A” when asked for “days from A to B”. Anything that divided one count by another came out right (the minus signs cancel), so no premium had been wrong yet. But “days until TRIA expires” came out negative. That field drives terrorism proration, which chunk 13 now depends on.

Technical
  • _date_difference returns (second − first).days; it returned (first − second).days.
  • Open consideration: the only GL rules using DateDifference are the ERP SetMaturity*Year rules, their operand order differs by edition, and no GL suite exercises them. The GL suites passing says nothing broke that they test, not that GL ERP maturity is now right. Logged on OI-107.
Evidence
  • Live ISO, Oregon: DaysUntilTRIAExpiration ISO 257, ours −257 before, 257 after. Pinned in the regression (120_). Regression clean, 68 of 68.

7 “Stop the loop” inside a sum lost the sum (OI-108) 2026-09-23 ISO-confirmed 8 of 8

In plain English. In the older California, North Carolina and Missouri editions, the drone rule adds up drone limits and, for a blanket drone, says “take the blanket limit, then stop”. Our engine stopped before taking it, so a blanket drone’s $99,000 limit read as $0. That limit drives the drone deductible, so we undercharged by about $125 in NC and MO.

Technical
  • A Break inside a Sum raised BreakLoop before the Sum returned, and _for_each recorded the iteration as nothing. Now the Sum finishes over the operands already added, and ForEach records that total (BreakLoop.value).
  • Only 6 of 21,037 operators in chunk 12’s files had this shape; the 2026 edition rewrote the rule without the Break, which is why 42 states were unaffected.
Evidence
  • Live ISO: TotalScheduleLimit 99,000 in CA, NC, MO (ours was 0); after the fix CA/NC/MO/GA 8 of 8 identical, limit and premium. Regression clean.

8 A premium with a missing input no longer stops the rating (OI-109) 2026-09-23 Narrowed by #9 the same day

In plain English. Ordinance or Law sent without its demolition limits: ISO rated the policy and showed those two parts at $0; we refused the whole submission, because our engine treated a missing premium as an error (“money can’t be blank”). This change let Property write $0 for a premium that comes out blank. The same day, a sharper probe showed ISO’s real rule is different (#9), so this now applies only when every input to a premium is missing.

Technical
  • New interpreter mode null_premium="zero" under propagate (Property): a null premium is written as 0, traced null-premium-zeroed, listed in Interpreter.null_premiums. GL keeps refuse.
  • Four zero-case scripts that pinned the old refusal were updated with the old wording kept.
Evidence
  • 5 of 5 live probes matched ISO, messages included; regression clean. But all 5 probes had rates that rounded to $0 anyway, so they could not tell “write $0” from “skip the missing value”. That gap is what #9 closed.

9 A missing input in a multiplication is skipped, as ISO does (OI-110) 2026-09-23 ISO-confirmed $1 / $3 / $5

In plain English. A Builders Risk reporting form with no limit: ISO charged $1, we charged $0. ISO doesn’t treat the missing limit as zero; it leaves it out of the multiplication and multiplies what’s left. Rate 0.500 times “nothing” is 0.500, which rounds to $1. Probes built so the two readings gave different answers ($3 and $5 against our $0) settled it.

Technical
  • Property’s Product skips a null operand (nodes._product, Interpreter.product_skips_null), recording each skip in null_skips and the trace (product-null-skipped). #8’s zero-write remains only for a product whose operands are all null. GL untouched.
  • It uncovered a hidden difference: chunk 5’s Combined-risk zero case now matches ISO ($256 + $30).
  • Standing rule it produced: a probe only proves a rule if competing rules predict different answers on it.
Evidence
  • All 9 null-handling probes agree live, including the three that discriminate. Interpreter tests 71/71. Regression clean.

10 “Go up to the record called X” finds that record (OI-111) 2026-09-24 Matches ISO 14 of 14

In plain English. California caps terrorism at 25% of the rest of the policy premium. To get that total, its rule says “go up to the policy and add up its premium”. Our engine ignored the name “policy” and jumped to the very top of the document, where there are no locations, so the total read $0 and terrorism was capped at $0. ISO found a $3,424 total and charged $153. We had learned to ignore the name from General Liability, where it names the document itself and never matches; Property uses the same syntax to name real records.

Technical
  • tree.py: an ancestor::Name step now resolves to the nearest ancestor-or-self tagged Name, and to the root only if none matches (_ancestor, used by both select and ensure). GL’s ancestor::MasterGLCW never matches a node while rating MasterGLOK, so it still falls through to the root: unchanged by construction.
  • Reach: 30,512 ancestor:: paths in the CF corpus, about 1,500 root-shaped and ~29,000 naming records (CommercialPropertyStructure 13,450; CommercialProperty 7,773; ~60 others). Chunks 1–12 had matched ISO regardless, and the regression shows none of their figures moved.
  • Open consideration: the “-or-self” part (a rule running on the policy record that names the policy) is the reading the probe tested and ISO confirmed on these cases, but no case yet exercises it directly.
Evidence
  • Probe with the engine untouched (146_): the named reading matched ISO on both CA cases, the old reading didn’t, GA and NY agreed either way. After the fix: replay 14 of 14 stored ISO terrorism responses; full regression clean (82 checks incl. all GL suites); CA $153 pinned in the regression (145_).

The pattern behind all ten. Every one surfaced where a Property coverage used a rule shape that no earlier case, and no General Liability case, had ever run: a new loop form, a two-bracket table, dates, 00, a stop inside a sum, a missing input, a named ancestor. The engine was never wrong about what it had already been tested on. That’s why each chunk opens with a census of rule shapes and value types, and why a fix only counts once a case that could have disagreed with ISO doesn’t.
