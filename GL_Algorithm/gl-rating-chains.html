Nineteen chains across eight sublines, none of them a template

Unlike CF's four cause-of-loss forms rated in parallel off one shared shape, GL's eight sublines share almost nothing structurally — Premises/Operations forks by countrywide edition, Products/Completed Operations forks by whether a published loss cost is filed as zero, Owners & Contractors Protective forks by class code and by edition simultaneously, Railroad Protective forks by class code four ways with three "naming trap" rules whose names lie about which class they test, and Product Withdrawal / Cyber reads its host coverage's already-computed values rather than its own tables (escalation E18). Liquor Liability is the plainest of the eight: no loss-cost path exists at all, by rule — Rule 45.E says "for rates, refer to company," so the entire chain is an ELP-driven surrogate. Stop Gap Employers Liability is the only one with no ISO subline code and no countrywide rating package at all — it is filed state-only, in exactly five monopolistic-fund jurisdictions, and its rate build-up reads Premises/Operations' own already-computed BaseRate and exposure count directly, the same E18 pattern Product Withdrawal / Cyber uses but at the level of computed values rather than borrowed tables.

Dashed amber-and-rust nodes mark a flagged finding — an unresolved formula, a naming trap, a sibling-group dependency, a table that prices legitimately at zero — logged in each subline's own RatingAlgorithms.md and its source gate doc rather than guessed at. Where a gate doc did not reconstruct a step's internal branching, the node says so instead of inventing one.

What to notice

  • There is no rate build-up here at all — the "rate" input is the already-computed `Premium` and `FinalILF` of three sibling coverage groups, so this chain must be the last thing rated in the policy (GATE-TERRORISM.md § 8.1).
  • 15 of 51 jurisdictions zero out the countrywide exposure-class-factor rows entirely and redirect to a state-suffixed, territory-keyed table with a 33x spread versus countrywide's 2.25x — this is a factor-resolution difference inside every aggregation path, not a separate premium chain.
  • `SetTerrorismILF` picks the sub-limit ILF two ways depending on whether the terrorism aggregate limit is at or below the policy per-occurrence limit (PEV001 A.1.c.(1)/(2)) — and the ratio divides by the host's `FinalILF`, not a terrorism-side value.
  • Resolved 2026-09-01: which form fires the NBCR factor is now known from a direct read of the manual's Terrorism Supplement — CG 21 84, offerable only after the insured first rejects standard A.1.a coverage. Which form kills the chain outright (CG 21 73/75/87/90) and which puts the aggregate-limit mismatch on the policy (CG 21 80/89/92) are resolved the same way.
Open question. The manual names which endorsement form does what; it does not say which policy-level DataDef or flag the rating engine actually reads to determine "which form is attached" — that mapping would need the rule file itself, not the Terrorism Supplement.
Reconciled against the engine, 2026-10-02. The chain drawn above multiplies optional factors together; the rule does not. SetPremium is a first-match choice: (1) TerrorismCoverage = Yes → round(ClassCoveragePremium × exposure-class factor, 0); else (2) an NBCR exclusion record exists (CG 21 84, and also 21 88 / 21 91) → × the NBCR factor 0.58; else (3) a cap / sublimit record exists (CG 21 80 / 82 / 89 / 92) → round(round(CCP × factor, 0) × round(TerrorismILF ÷ host FinalILF, 3), 0); else 0 — then a $1 floor in CW 2027 only. Exclusion forms CG 21 73 / 75 / 87 / 90 only raise validation messages. So a declined policy with a cap endorsement is still charged: Oklahoma's base rates terrorism 2 + 16 = 18, matching ISO's own output (account 8,229). FL and NY override to a Yes-only formula (NY needs the Manhattan input — without it the engine silently prices $0, an engine/register gap); AK drops CG 21 84 from the NBCR test.

What to notice

  • Two separate E18 reads, not one: Step 3 reads Prem/Ops' own classification `BaseRate` directly (not a lookup table), and Step 4 reads Prem/Ops' own `PremOpsExposureCalc` — Stop Gap has no exposure base or base rate of its own at all. This is a deeper form of the pattern Product Withdrawal / Cyber uses (which borrows tables but not already-computed sibling values).
  • The classification-level limit-equality branch (Step 4) and the policy-level branch (Premium aggregator) test the identical condition twice, at two different levels — when limits differ, every classification's `StopGapPremium` is forced to 0.0 and the policy-level aggregator abandons the sum entirely in favor of the submission-supplied `ManualPremium` path.
  • The countrywide `StopGapRate` table is confirmed 0 rows at every edition checked — there is no countrywide fallback for the rate factor; all five rating states must carry their own row for every `ClassificationType`, and 25/25 cells across the five states match the manual's two-bucket table exactly.
  • No rating-mechanism deviation was found among the five states beyond the endorsement form number itself (CG 04 40/41/42/44/51) — same rule names, same call order, same two factor values, same ILF borrow, same refer-to-company mechanism in all five.
Open question. Three things are unresolved in source docs: what populates `StopGapIncrdLimitFactorOverride` and under what submission condition; whether `PackageModFactor`, `ExperienceRatingModificationFactor`, and `ModToUse` are filed rate tables or policy-level copied values (the same open question the Unmanned Aircraft docs record for the identically-named fields); and whether WA's newest package on disk reflects a live 2027-04-01 filing that simply wasn't pulled into this corpus.
